# Academic site — Z. Carton Zeng

Static site, no build step. Every page is plain HTML that can be opened directly
in a browser or served from any static host.

Design decisions and the reasoning behind them live in
[`docs/personal-website-plan.md`](docs/personal-website-plan.md).

## Layout

```
index.html                  Home: positioning, news, contact
research.html               The roadmap diagram and one block per paper  ← the core page
publications.html           Word cloud + all 14 papers in three groups
talks.html                  Talks and slides, grouped by topic
cv.html                     PDF embed and download
misc.html                   Non-academic page
misc-thoughts.html          The physics–history–games "daydream" essay
dwarf-diversity-tracks.html Full tidal-track catalog for arXiv:2412.14621

assets/css/site.css         All styling
assets/img/                 Portrait, word cloud, paper figures
assets/cv/                  Zeng_CV.pdf
assets/slides/              Talk slides (PPTX)

scripts/                    Word cloud generator, link checker
docs/                       Plan document and reference material
```

## Working on it

Preview locally:

```
python -m http.server 8765
```

then open <http://127.0.0.1:8765/>. Any editor works; there is nothing to compile.

The navigation bar and footer are duplicated across all pages. That is a
deliberate trade-off for having no build step — if you change a nav item, change
it in every file.

## Word cloud

`assets/img/wordcloud.svg` is generated by `scripts/generate_wordcloud.py` and
committed to the repo, so it does not need to be rebuilt to deploy. Regenerate
it only after adding a new paper: add the paper to the `PAPERS` list in the
script and run it. The script reads the paper titles plus, if present, extracted
text placed under `data/abstracts/` or `data/fulltext/`.

## Publishing to GitHub Pages

1. Create a repository named `<username>.github.io`
2. Push these files to the default branch
3. Settings → Pages → deploy from branch, root folder

The site appears at `https://<username>.github.io/` within a minute or two. No
CI or build configuration is needed.
